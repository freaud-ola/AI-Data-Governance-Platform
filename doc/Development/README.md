## 写作约定

1. **每次 Sprint / 一次较大开发** 都新建一个文档，命名 `0X-SprintXX-标题.md`。
2. 每篇文档建议包含：
   - **本次目标**：一句话说明本次要解决什么
   - **完成项**：列出实际产出（含代码路径）
   - **关键决策**：选型、取舍、理由
   - **已知问题 / 技术债**：写清楚后续要补的坑
   - **下次接续点**：明确下一次开始时该看什么、做什么
3. 不再维护的内容用 `~~删除线~~` 或移到末尾归档。
4. 涉及架构变更时，必须同步更新 `doc/Architecture/` 对应章节。
5. 配置示例统一用 YAML / JSON；命令一律 bash。

---

## 与架构文档的关系

```
doc/
├── Architecture/    ← 设计 (Design)：长期稳定，回答 "WHAT / WHY"
└── Development/     ← 开发 (Build) ：高频更新，回答 "HOW FAR / NEXT"
```

- 架构文档：**做什么、为什么这样做**（决策驱动）
- 开发日志：**做到哪了、下一步怎么做**（进度驱动）

两者交叉引用：架构变更触发开发日志记录；开发遇到无法落地的设计须回写到架构。
